## 1. 运行模式与回复模式（两套正交状态）

### 1.1 能力模式（是否用模型）—— 全局唯一

```text
model_enhanced ──用户切换──▶ local_rules_only
       ▲──────────────────────────
```

| 状态 | 含义 | AI 调用 |
|---|---|---|
| `model_enhanced` | 模型增强（端点=远程 API 或本机 Ollama/LM Studio） | ✅（端点按 AI 配置） |
| `local_rules_only` | 纯本地规则 | ❌ 全部禁用（含 jev/嵌入） |

**切换规则**：切到 `local_rules_only` 时，回复模式强制降为 `observe`（见 §1.2），需用户重新确认升级。

### 1.2 回复模式 —— 全局三态 + 会话覆盖

```text
                    ┌──────────┐
        ┌──────────▶│ OBSERVE  │（首次启动默认；学习不回复）
        │           └──────────┘
        │ 切换(需:数据READY+AI配置有效,否则ret=422)
        │           ┌──────────┐
        ├──────────▶│  SUGGEST │（生成建议卡，用户拍板）
        │           └──────────┘
        │ 切换(需:SUGGEST稳定运行+用户二次确认)
        │           ┌──────────┐
        └───────────┤   AUTO   │（定时发送，过闸门）
                    └──────────┘
任何态 ──暂停(paused,source=ui|wxbot)──▶ 恢复回原态
任何态 ──降级(degraded: token超限/AI连续失败/hook失效)──▶ 向左退一档 + 通知
```

| 疑义 | 裁定 |
|---|---|
| 首次启动默认？ | **OBSERVE**（不是 SUGGEST——数据未就绪时禁一切发送，04 §5.3） |
| 会话级 override？ | **五值** `inherit|off|observe|suggest|auto`（T01 统一，原 on 语义拆分为 suggest/auto）；覆盖只改本会话处理方式，**不能解除全局暂停、不能突破正式策略** |
| 切换需确认？ | OBSERVE→SUGGEST、SUGGEST→AUTO 均需；降级不需要 |

## 2. 消息事件状态

消息本身无长状态机，但**来源五维标注**决定其可用性（07 §1.2）：

```text
ingest_source: live_hook | history_import
direction:     inbound | outbound
author_role:   me | contact | system | unknown
outbound_origin: manual | ai_suggestion | ai_auto | unknown   (仅 outbound)
identity_confidence: verified | uncertain
```

| 组合 | 可用性 |
|---|---|
| outbound + me + manual + verified | 强学习证据（明确纠正 → 高优先级候选） |
| outbound + me + **unknown**（历史导入必然如此） | 仅弱观察统计，**不得作强学习证据** |
| outbound + me + ai_auto/ai_suggestion | **不作本人风格样本**（系统指标可用） |
| 任意 + uncertain | **不参与任何学习** |

## 3. 学习任务状态机（outbox_jobs，失败可重试）

```text
pending ──领取──▶ running ──成功──▶ succeeded
                    │失败(attempts<max)
                    ▼
               retry_wait ──退避到期──▶ running
                    │attempts≥max_attempts
                    ▼
               dead_letter ──用户查看/手动处理/丢弃
```

| 规则 | 内容 |
|---|---|
| 幂等 | `idempotency_key` UNIQUE；重复消费不重复产出候选 |
| 输入变更 | `input_hash` 不同 → **新任务**，不覆写旧结果 |
| 优先级 | 实时回复相关 > 历史批处理 > 语义索引；**学习失败不影响发送链路** |
| 暂停 | 用户可暂停批处理；收消息/人工发送不受影响 |

## 4. 发送任务状态机（pending_send，与学习任务严格分离）

```text
                     ┌──────────────────────────────────────────┐
                     │  前置校验(生成后立即): 模式/接管/勿扰/风险    │
                     └────────────────┬─────────────────────────┘
                                      ▼
                                 ┌─────────┐
              ┌────取消──────────▶│scheduled│
              │ (session_version │└────┬────┘
              │  变更/接管/过期)  │     │ 到点 + 四项校验全过(02 §3.2)
              │                  ▼     ▼
   ┌──────────────────────┐   ┌─────────┐
   │cancelled             │◀──│sending  │
   └──────────────────────┘   └──┬───┬──┘
              ▲            确认回执│   │已下发但确认前崩溃
              │                   ▼   ▼
         ┌────────┐      ┌──────────────┐ ┌───────────────────┐
         │sent_   │◀─核验─│sent_confirmed│ │sent_result_unknown│★
         │failed_ │ 核验  └──────────────┘ └───────────────────┘
         │definitive│      ▲                   │
         └────────┘      └───────核验确认未发送──┘ → 允许重发
```

**★ `sent_result_unknown` 是重复发送的唯一防线**（评审七）：

| 情况 | 处理 |
|---|---|
| 已下发但确认回执前崩溃 | 标 `sent_result_unknown`；恢复后**先核验**（按 idempotency_key 查发送历史/会话最近消息） |
| 核验确认已发送 | → `sent_confirmed`，**禁止重试** |
| 核验确认未发送 | → 允许重发（走完整四项校验） |
| 核验仍无法确定 | → 转建议卡/人工，**不自动重发** |

四项发送前校验（任一失败即 cancelled + 原因码）：①session_version 匹配 ②last_inbound_msg_id 仍是最后入站 ③模式/接管/勿扰允许 ④未过期。

## 5a. 回复建议状态机（T03：与发送任务分离，评审十一）

```text
generated ──▶ pending_review ──批准──▶ approved ──创建发送任务──▶ (转 §4 外发状态机)
                  │                       │
                  ├─拒绝(带原因码)──▶ rejected      │发送任务失败≠批准失效
                  ├─30min超时──────▶ expired        │（批准记录仍在）
                  └─会话变化──────▶ cancelled
```

- **批准 ≠ 已发送**：用户批准只表示"允许创建发送任务"；外发失败时批准记录仍在（学习信号独立计算）。
- **编辑保留原版**：编辑后生成新候选版本，原始候选保留——用于 diff 分类（T05）与学习比较。
- 状态：`generated / pending_review / approved / rejected / expired / cancelled`。

## 5b. 外发任务状态机（T03：完整字段契约）

```text
pending → sending → confirmed            （有可靠发送回执）
                  → unknown              （已下发，确认前中断——禁止直接重试）
                  → failed               （明确失败，按 failure_code 定重试）
pending/sending → cancelled              （会话变化/接管/过期/用户取消）
```

**任务完整字段**（重复文本 ≠ 重复任务——用户可能真的要再发同一句）：

```sql
CREATE TABLE send_tasks (
  task_id TEXT PRIMARY KEY,
  idempotency_key TEXT UNIQUE,
  conversation_id TEXT NOT NULL,
  reply_id TEXT,                          -- 关联建议/来源
  conversation_version INTEGER NOT NULL,  -- 生成时会话版本（过期判定）
  payload_hash TEXT NOT NULL,             -- 待发内容哈希（防中途篡改）
  status TEXT NOT NULL CHECK (status IN
    ('pending','sending','confirmed','unknown','failed','cancelled')),
  attempt_count INTEGER NOT NULL DEFAULT 0,
  last_attempt_at INTEGER,
  confirmed_at INTEGER,
  external_receipt_id TEXT,               -- 发送回执（确认成功的证据）
  failure_code TEXT,                      -- STANDARDIZED 错误码（§12）
  created_at INTEGER NOT NULL
);
```

幂等键解决**重复创建任务**；外部操作不重复靠 §4 的 **unknown → 核验** 闭环——两者缺一不可。

## 6. 记忆状态机（双维，04 §3.3；T06 字段规范化）

**标准字段语义**（防"大杂烩"表）：

| 字段 | 解决的问题 |
|---|---|
| `scope_type/scope_id` | 适用于谁或什么范围 |
| `category` + `memory_key` | 类别 + 同一事项规范化标识（冲突检测键） |
| `review_status` + `lifecycle_status` | 候选/确认/拒绝 + 有效/被替代/归档 |
| `memory_evidence` | **根据什么产生**（来源消息/文档，可追溯） |
| `valid_from/valid_until` | 事实何时有效 |
| `memory_relations.supersedes` | 新记忆替代了哪条旧记忆 |

无可靠来源 → 标记为无来源候选，**不与已确认事实同等对待**；`confidence` 只是证据估计，**不是正确性证明**——证据弱/有冲突/随时间变化仍须请求确认。

**冲突处理五步**（04 §3.6 的执行细则）：识别同一事项（memory_key）→ 判断新信息是否明确修改旧安排 → 保留来源与时间 → 旧记录标 superseded → 新记录设当前有效；**有歧义先求确认**。区分"事实变化"（适合更新）与"描述矛盾"（保留争议状态）。

**检索 = 硬过滤 + 多维排序**：召回**前**硬过滤（已撤销/已过期/作用域不符/来源失效——不靠分数）；排序 = `w_r·相关度 + w_t·时间有效性 + w_c·来源可信度 + w_s·作用域匹配 + w_e·证据完整度`，**权重经测试集校准，不凭经验拍定**。过期报价/取消的会议即使语义高度相关也不进 prompt。

```text
审核:   candidate ──确认──▶ confirmed ──拒绝(候选)──▶ rejected
生命周期: active ──被取代──▶ superseded ──用户归档──▶ archived
                  └─过期──▶ (active但valid_until已过，检索自然排除，不强制改态)
```

进 prompt 充要条件：`confirmed + active + 作用域允许 + valid_from≤now<valid_until + 未被 supersedes 指向 + 相关 + 预算内`。

## 8. 知识文档版本状态机（04 §7.2）

```text
staging ──预览通过──▶ preview ──用户审核──▶ published（原子切换 active_version）
```

## 9. 模型调用故障分类（评审九：不允许失败绕过安全闸门）

| 故障 | 判定 | 处理 | 是否可重试 |
|---|---|---|---|
| 超时 | >8s（jev）/ >30s（生成） | jev: 按 risk=high 转人工；生成: 转建议或静默 | jev 否；生成同会话 3 次失败暂停 30min |
| 输出格式错误 | JSON 解析失败 | 同上 fail-safe；有限重试 1 次 | 有限 |
| 风险判断失败 | jev 字段缺失 | 保守默认 `risk=high` → **转人工** | ❌ |
| 上下文不足 | 新联系人/无历史 | 冷启动保护：建议模式+保守 prompt，**不编造** | — |
| 连续失败 | 同会话 3 次 | 暂停 30min + 通知 + 会话转人工 | — |
| 认证/配额错误 | 401/429 | 直接暂停对应档案 + 通知（不退避重试轰炸） | ❌ |

**铁律：任何故障路径的出口只能是 observe 行为或人工，不能是 auto 发送。**

## 10. jev 决策契约 v2（T02：三态决策，评审十 10.2）

```json
{
  "schema_version": 1,
  "decision": "reply | ignore | human",
  "risk_level": "low | medium | high",
  "urgency": "low | normal | high",
  "intent": "question | greeting | chat | request | closing | unknown",
  "needs_human": false,
  "reason_code": "DIRECT_QUESTION",
  "policy_refs": ["strategy:style.brevity@3"]
}
```

| 字段 | 约束 |
|---|---|
| `schema_version` | 运行时校验；未知版本按格式错误处理，**不猜** |
| `decision` | **三态**：reply / ignore / human —— 消除 `should_reply=false 且 needs_human=true` 的歧义（v1 的 should_reply 废弃） |
| `risk_level` | 未知时**不得默认 low**（保守默认 high → human） |
| `needs_human` | true → 禁止自动发送 |
| `reason_code` | 标准原因码枚举（统计/测试/诊断用），附简短 reason 文本供用户查看 |
| `policy_refs` | 只允许引用系统内有效策略标识 |

**模型输出仅是候选决策，不是执行授权**——最终能否回复由 Rust 规则引擎 + 发送闸门裁决（§4/§8）。
不要求模型输出内部推理；只留简短原因 + 命中规则 + 证据引用，减少无关内容进日志。

### 10.1 统一失败矩阵（保守降级，评审十 10.3）

| 故障 | 行为 |
|---|---|
| 决策模型超时 | 不自动发送，按策略转人工 |
| 返回不合法结构 | 不自动发送，记录结构错误 |
| 上下文不完整 | 重新读取或转人工，**不补造事实** |
| 风险判断无法确定 | 按高风险处理 |
| 生成回复为空 | 取消任务或提示重新生成 |
| 正式规则已失效 | 重新决策，**不套用旧规则** |
| 会话状态生成后改变 | 取消旧任务或重新生成（§4 状态机） |
| 发送状态无法确认 | 标结果未知，进核验流程 |

本地规则模式同规：**依据不足宁可不动，不为回复率猜测。**

### 10.2.1 运行参数

| 项 | 定义 |
|---|---|
| 输入 | 会话最近 N 条（脱敏后）+ 新消息 + 关系标签 |
| 输出 | `{should_reply, risk, urgency, intent, needs_human, reason}`（六字段，v1.1） |
| 超时 | 8s |
| 错误分类 | 超时/格式错/字段缺失 → 全部按 fail-safe（§9） |
| 降级 | jev 不可用 → 全部转建议卡，**不影响 observe/手动链路** |
| 评估 | 上线后用回复质量集回测 `should_reply` 准确率，每周出报告 |

## 11. 数据保留与删除（评审三：生命周期明确）

| 数据类别 | 默认保留 | 删除联动 |
|---|---|---|
| 原始消息 events | 90 天滚动（live）；历史导入**永久**（用户可清） | 删消息 → 证据失效 → 候选重估 → 画像重算（04 §3.7 血缘链） |
| 运行日志 ai_logs | 30 天 | 到期清理，不联动 |
| 学习产物 outbox/observations | 随源数据 | 源删则任务/观察失效 |
| 已确认记忆 | 永久（用户显式删） | 删除走 04 §3.7 完整链 |
| 建议卡 | 7 天 | 到期清理 |

**数据分级与模块访问边界**（评审三：最小必要）：

| 类别 | 谁可读 |
|---|---|
| 原始消息正文 | 编排器上下文组装、历史导入、记忆提取（outbox 任务内）；**画像统计只读聚合不出原文** |
| 长期记忆 | 记忆模块 + 编排器（检索路径内） |
| 画像 | 编排器（节奏/决策）；**不需要原文** |
| 日志 | 无业务模块读 |

## 11b. 统一发送闸门（T04：唯一强制校验模块，评审十 10.1）

**十步权威决策序**（任何入口——UI/手机指令/后台任务——必须走同一套）：

```text
 01 全局状态检查    暂停/回复模式/会话接管
 02 事件有效性      去重/方向/来源与身份可信度
 03 本地硬规则      消息类型/黑名单/勿扰/会话权限/额度
 04 标准规则匹配    仅"范围明确+已生效"的正式规则
 05 AI 回复决策     jev（reply/ignore/human + risk）
 06 上下文构建      最近对话/记忆/画像/已确认策略（§15 预算序）
 07 回复生成与校验  候选/事实检查/重复检测/风险复核
 08 任务调度        有效期/撤销窗口/会话版本/并发
 09 最终发送检查    ★再次检查暂停/会话变化/任务有效性（不因几秒前通过而豁免）
 10 结果核验与反馈  确认发送状态/记录结果/生成学习信号
```

**三个核心区别**：
1. **硬规则 > 模型判断**——黑名单/全局暂停/接管/高风险拦截不能靠改提示词、换模型或重试绕过；
2. **标准规则 > 重新生成**——已确认且精确命中的固定话术直接进审核/执行流，语义不确定不硬套；
3. **最终发送检查必须重跑**——建议卡批准、延迟计时到实际发送之间状态可能已变。

实现：`autoreply-core::send_guard` 是**唯一**闸门模块；wxbot/UI/后台任务不各自实现近似逻辑。

## 12b. WS 可恢复事件协议与统一错误码（T07，评审十五）

**事件帧升级**（客户端按 seq 检查断档，断档→请求对账，不盲目覆盖）：

```json
{"event_id":"evt_…","sequence":1082,"event_type":"suggestion.updated",
 "entity_id":"sg_…","entity_version":3,"occurred_at":1791907200000}
```

**统一错误码**（HTTP 状态码承载传输层语义，业务码承载业务语义；UI 不解析错误文本）：

| 错误码 | 含义 | 客户端行为 |
|---|---|---|
| VALIDATION_ERROR | 参数不合法 | 提示修改 |
| STATE_CONFLICT | 资源状态已变化 | 重新获取状态后处理 |
| RESOURCE_NOT_FOUND | 不存在 | 刷新或提示 |
| POLICY_BLOCKED | 正式策略阻断 | 展示阻断原因 |
| TASK_EXPIRED | 任务已过期 | 不重试原任务 |
| MODEL_TIMEOUT | 模型超时 | 按降级策略 |
| MODEL_INVALID_OUTPUT | 输出不符契约 | 记录并转人工 |
| SEND_RESULT_UNKNOWN | 发送结果未知 | 进入核验流程 |
| QUOTA_EXCEEDED | 超额度 | 降级或等待恢复 |
| INTERNAL_ERROR | 未分类 | 生成关联 ID 记录诊断 |

**写接口幂等性契约**（每个状态变更接口必须声明）：是否支持幂等键 / 键保留多久 / 重复请求返回什么 / 并发是否要求 expected_version / 失败可否安全重试 / 完成后发什么事件。

## 1.2b 会话覆盖与全局暂停（T01：三个独立概念，评审十八 P0）

```text
global_mode:         observe | suggest | auto        （全局回复模式）
conversation_override: inherit | off | observe | suggest | auto   （会话级覆盖，五值）
global_paused:       true | false                    （全局暂停，独立布尔）
```

**执行优先级**：`global_paused=true` > 会话 override > global_mode。
覆盖仅改变该会话处理方式：**不能解除全局暂停**、不能突破正式策略、不能绕过风险硬规则。
`off=永不自动`；`observe=只学不回`；`suggest=只出建议卡`；`auto=允许进发送闸门（仍过 §4 校验）`。

## 13b. 可观测性与成本（T09，评审十六/十七）

**trace_id 贯穿**：接入→标准化→决策→上下文→生成→校验→建任务→核验→反馈，同一 trace_id 关联；四类记录分离（运行日志/业务审计/性能指标/学习证据），保留周期与权限独立。

**最小仪表盘指标**：运行模式与接管态 · 近 1h 收/建议/发数量 · 各阶段耗时与模型 P50/P95 · 待审核/待发送/**结果未知**/失败数 · 当日调用量与预算剩余 · 错误与策略阻断原因 · 学习任务积压与未确认记忆策略数。
**「结果未知」任务数单独展示**——它直接决定用户是否需要人工核验，不得藏在失败日志里。

**调用分层策略（省成本）**：本地硬规则始终先执行 → 过门控才调决策模型 → 低风险一次生成（失败按明确条件重试）→ 高不确定性才加校验 → 风险无法判定转人工。**多候选首版只生成 1 个**，点「换一个」再生成第二个。全局+单会话两级额度（次数/Token/并发），将尽时降观察模式。

## 14 · 全自动模式准入门槛（评审十九：不是用户点开关就开）

从 SUGGEST 升级 AUTO 前必须通过（全部自动化测试，结果随版本保存）：

| # | 验收项 | 门槛 |
|---|---|---|
| 1 | 风险拦截 | 固定高风险测试集**全部**正确拦截（错误自动发送 = 0） |
| 2 | 人工接管 | 接管生效后所有未发送相关任务全部拦截（= 0 泄发） |
| 3 | 任务状态 | 超时/过期/取消/重启恢复/结果未知全有明确处理结果 |
| 4 | 记忆隔离 | 测试中跨联系人记忆泄漏 = 0 |
| 5 | 回复质量 | 低风险测试集达到约定上下文准确率与人工接受率基线 |
| 6 | 异常恢复 | 故障注入（事务前/后、调度前、下发后确认前）全过，无重复任务/丢状态 |

测试规模：约 300 个脱敏分层抽样场景（闲聊/提问/结束语/事实不明/规则冲突/人工介入/异常恢复）。
**安全门槛不满足 → 继续用观察或建议模式；不得为提高自动回复率放宽高风险限制。**
