## 1. 运行模式与回复模式（两套正交状态）

### 1.1 能力模式（是否用模型）—— 全局唯一

```text
model_enhanced ──用户切换──▶ local_rules_only
       ▲──────────────────────────
```

| 状态 | 含义 | AI 调用 |
|---|---|---|
| `model_enhanced` | 模型增强（端点=远程 API 或本机 Ollama/LM Studio） | ✅（端点按 AI 配置） |
| `local_rules_only` | 纯本地规则 | ❌ 全部禁用（含 jev/嵌入） |

**切换规则**：切到 `local_rules_only` 时，回复模式强制降为 `observe`（见 §1.2），需用户重新确认升级。

### 1.2 回复模式 —— 全局三态 + 会话覆盖

```text
                    ┌──────────┐
        ┌──────────▶│ OBSERVE  │（首次启动默认；学习不回复）
        │           └──────────┘
        │ 切换(需:数据READY+AI配置有效,否则ret=422)
        │           ┌──────────┐
        ├──────────▶│  SUGGEST │（生成建议卡，用户拍板）
        │           └──────────┘
        │ 切换(需:SUGGEST稳定运行+用户二次确认)
        │           ┌──────────┐
        └───────────┤   AUTO   │（定时发送，过闸门）
                    └──────────┘
任何态 ──暂停(paused,source=ui|wxbot)──▶ 恢复回原态
任何态 ──降级(degraded: token超限/AI连续失败/hook失效)──▶ 向左退一档 + 通知
```

| 疑义 | 裁定 |
|---|---|
| 首次启动默认？ | **OBSERVE**（不是 SUGGEST——数据未就绪时禁一切发送，04 §5.3） |
| 会话级 override？ | `inherit/on/off/observe` 四值；`observe` 覆盖全局 AUTO（04 §5.3） |
| 切换需确认？ | OBSERVE→SUGGEST、SUGGEST→AUTO 均需；降级不需要 |

## 2. 消息事件状态

消息本身无长状态机，但**来源五维标注**决定其可用性（07 §1.2）：

```text
ingest_source: live_hook | history_import
direction:     inbound | outbound
author_role:   me | contact | system | unknown
outbound_origin: manual | ai_suggestion | ai_auto | unknown   (仅 outbound)
identity_confidence: verified | uncertain
```

| 组合 | 可用性 |
|---|---|
| outbound + me + manual + verified | 强学习证据（明确纠正 → 高优先级候选） |
| outbound + me + **unknown**（历史导入必然如此） | 仅弱观察统计，**不得作强学习证据** |
| outbound + me + ai_auto/ai_suggestion | **不作本人风格样本**（系统指标可用） |
| 任意 + uncertain | **不参与任何学习** |

## 3. 学习任务状态机（outbox_jobs，失败可重试）

```text
pending ──领取──▶ running ──成功──▶ succeeded
                    │失败(attempts<max)
                    ▼
               retry_wait ──退避到期──▶ running
                    │attempts≥max_attempts
                    ▼
               dead_letter ──用户查看/手动处理/丢弃
```

| 规则 | 内容 |
|---|---|
| 幂等 | `idempotency_key` UNIQUE；重复消费不重复产出候选 |
| 输入变更 | `input_hash` 不同 → **新任务**，不覆写旧结果 |
| 优先级 | 实时回复相关 > 历史批处理 > 语义索引；**学习失败不影响发送链路** |
| 暂停 | 用户可暂停批处理；收消息/人工发送不受影响 |

## 4. 发送任务状态机（pending_send，与学习任务严格分离）

```text
                     ┌──────────────────────────────────────────┐
                     │  前置校验(生成后立即): 模式/接管/勿扰/风险    │
                     └────────────────┬─────────────────────────┘
                                      ▼
                                 ┌─────────┐
              ┌────取消──────────▶│scheduled│
              │ (session_version │└────┬────┘
              │  变更/接管/过期)  │     │ 到点 + 四项校验全过(02 §3.2)
              │                  ▼     ▼
   ┌──────────────────────┐   ┌─────────┐
   │cancelled             │◀──│sending  │
   └──────────────────────┘   └──┬───┬──┘
              ▲            确认回执│   │已下发但确认前崩溃
              │                   ▼   ▼
         ┌────────┐      ┌──────────────┐ ┌───────────────────┐
         │sent_   │◀─核验─│sent_confirmed│ │sent_result_unknown│★
         │failed_ │ 核验  └──────────────┘ └───────────────────┘
         │definitive│      ▲                   │
         └────────┘      └───────核验确认未发送──┘ → 允许重发
```

**★ `sent_result_unknown` 是重复发送的唯一防线**（评审七）：

| 情况 | 处理 |
|---|---|
| 已下发但确认回执前崩溃 | 标 `sent_result_unknown`；恢复后**先核验**（按 idempotency_key 查发送历史/会话最近消息） |
| 核验确认已发送 | → `sent_confirmed`，**禁止重试** |
| 核验确认未发送 | → 允许重发（走完整四项校验） |
| 核验仍无法确定 | → 转建议卡/人工，**不自动重发** |

四项发送前校验（任一失败即 cancelled + 原因码）：①session_version 匹配 ②last_inbound_msg_id 仍是最后入站 ③模式/接管/勿扰允许 ④未过期。

## 5. 建议卡状态机

```text
pending ──┬─ 用户发送(edited?)──▶ sent
          ├─ 用户忽略 ──────────▶ discarded（不计负反馈）
          ├─ 30min 超时 ────────▶ expired（灰条，可手动回复）
          └─ 触发人工(T6 重要会话)──▶ escalation + 保持 pending
```

## 6. 记忆状态机（双维，04 §3.3）

```text
审核:   candidate ──确认──▶ confirmed ──拒绝(候选)──▶ rejected
生命周期: active ──被取代──▶ superseded ──用户归档──▶ archived
                  └─过期──▶ (active但valid_until已过，检索自然排除，不强制改态)
```

进 prompt 充要条件：`confirmed + active + 作用域允许 + valid_from≤now<valid_until + 未被 supersedes 指向 + 相关 + 预算内`。

## 7. 学习会话状态机（05 §11.1，13 态）

`NOT_STARTED / WAITING_FOR_DATA / ANALYZING_HISTORY / PREPARING_QUESTIONS / ASKING_USER / CLARIFYING / GENERATING_STRATEGY / WAITING_FOR_REVIEW / APPLYING_STRATEGY / COMPLETED / PAUSED / FAILED / CANCELLED`

崩溃恢复语义（05 §11.3）：已完成分析不丢、已存回答保留、生成中可重试、待确认恢复待确认、**已发布保持生效**。

## 8. 知识文档版本状态机（04 §7.2）

```text
staging ──预览通过──▶ preview ──用户审核──▶ published（原子切换 active_version）
   │                    │失败/放弃              │回滚
   ▼                    ▼                      ▼
 (丢弃)              failed                rolled_back（旧版重新激活）
```

规则：导入失败**不污染**当前 active 版本；同 SHA-256 重导入提示"内容未变化"。

## 9. 模型调用故障分类（评审九：不允许失败绕过安全闸门）

| 故障 | 判定 | 处理 | 是否可重试 |
|---|---|---|---|
| 超时 | >8s（jev）/ >30s（生成） | jev: 按 risk=high 转人工；生成: 转建议或静默 | jev 否；生成同会话 3 次失败暂停 30min |
| 输出格式错误 | JSON 解析失败 | 同上 fail-safe；有限重试 1 次 | 有限 |
| 风险判断失败 | jev 字段缺失 | 保守默认 `risk=high` → **转人工** | ❌ |
| 上下文不足 | 新联系人/无历史 | 冷启动保护：建议模式+保守 prompt，**不编造** | — |
| 连续失败 | 同会话 3 次 | 暂停 30min + 通知 + 会话转人工 | — |
| 认证/配额错误 | 401/429 | 直接暂停对应档案 + 通知（不退避重试轰炸） | ❌ |

**铁律：任何故障路径的出口只能是 observe 行为或人工，不能是 auto 发送。**

## 10. jev 组件契约（评审九：补独立运行说明）

| 项 | 定义 |
|---|---|
| 输入 | 会话最近 N 条（脱敏后）+ 新消息 + 关系标签 |
| 输出 | `{should_reply, risk, urgency, intent, needs_human, reason}`（六字段，v1.1） |
| 超时 | 8s |
| 错误分类 | 超时/格式错/字段缺失 → 全部按 fail-safe（§9） |
| 降级 | jev 不可用 → 全部转建议卡，**不影响 observe/手动链路** |
| 评估 | 上线后用回复质量集回测 `should_reply` 准确率，每周出报告 |

## 11. 数据保留与删除（评审三：生命周期明确）

| 数据类别 | 默认保留 | 删除联动 |
|---|---|---|
| 原始消息 events | 90 天滚动（live）；历史导入**永久**（用户可清） | 删消息 → 证据失效 → 候选重估 → 画像重算（04 §3.7 血缘链） |
| 运行日志 ai_logs | 30 天 | 到期清理，不联动 |
| 学习产物 outbox/observations | 随源数据 | 源删则任务/观察失效 |
| 已确认记忆 | 永久（用户显式删） | 删除走 04 §3.7 完整链 |
| 建议卡 | 7 天 | 到期清理 |

**数据分级与模块访问边界**（评审三：最小必要）：

| 类别 | 谁可读 |
|---|---|
| 原始消息正文 | 编排器上下文组装、历史导入、记忆提取（outbox 任务内）；**画像统计只读聚合不出原文** |
| 长期记忆 | 记忆模块 + 编排器（检索路径内） |
| 画像 | 编排器（节奏/决策）；**不需要原文** |
| 日志 | 无业务模块读 |

## 12. 隐私出网三级用户设置（评审三：可理解）

设置页「隐私」卡三选一 + 联系人级例外：

```text
① 仅本地规则     —— 任何内容不发给任何模型
② 云端按需脱敏   —— 只发当前任务所需上下文（默认）
③ 禁止云端处理名单 —— 指定联系人的消息永不进入模型调用（命中→转人工）
```

并附「最近一次模型调用」查看器：显示时间/端点/发送的数据类别与脱敏后长度（来自 ai_logs）。

## 13. 评估基线（评审六：三套独立数据集）

| 数据集 | 内容 | 用途 |
|---|---|---|
| A 回复质量 | 上下文理解/风格/事实准确/答非所问/无依据承诺 | 用户直接接受率、编辑幅度、拒绝率 |
| B 记忆质量 | 正确性/来源可溯/过时/跨联系人误合并/删除后失效 | 事实正确率、来源可溯率、过期比例 |
| C 系统可靠性 | 重复消息/超时/取消/崩溃恢复/并发 | 重复发送率、过期拦截率、结果未知处理正确率 |

**高风险单独门槛**（不能平均分掩盖）：跨联系人信息泄漏 = 0 起；未经授权自动发送 = 0 起。

**防泄漏切分**：按时间切——早期历史生成画像，后期未参与调参的记录评估；观察/建议模式积累真实反馈后才验证全自动。
